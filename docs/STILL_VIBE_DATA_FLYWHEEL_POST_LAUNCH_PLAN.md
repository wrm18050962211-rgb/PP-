# Still → Vibe 数据飞轮与研究衔接规划（上线后参考）

版本：v0.1

更新日期：2026-08-10

文档状态：延后规划 / 决策参考，不进入当前上线范围

适用项目：Still / PP、Vibe、多件服装试穿实验、未来 USYD 研究路径

> 本文用于保存一个上线后的长期假设：Still 在完成真实摄影服务后，可在明确授权、权利清晰和数据可追溯的前提下，把真实场景中的造型、选择和拍摄结果沉淀为 Vibe 的推荐、试穿评测及学术研究数据。本文不构成法律意见，也不授权当前版本立即收集或训练用户图片。

## 1. 当前决策

当前只保留规划，不实施训练数据功能，不修改当前上线优先级。

Still 近期仍按以下顺序推进：

```text
真实供给
-> 预约 / 订单 / 支付
-> 线下履约
-> 影像交付与售后
-> 复约、转介绍和单城验证
```

在上述闭环稳定前：

- 不把 AI 训练作为首发卖点；
- 不因未来训练计划批量收集非必要图片；
- 不默认把服务原图放入平台通用模型池；
- 不建设新的模型训练基础设施；
- 不把商业运营数据直接当作大学研究数据；
- 不因该设想影响 PTE、入学准备和 USYD 第一年的学业成绩。

该方向只有在真实业务证明 Still 本身有用户价值后，才可能成为第二增长曲线和长期数据壁垒。

## 2. 战略假设

普通网络图片通常缺少真实的用户意图、衣橱背景、场景目标、选择过程和结果反馈。Still 的潜在差异在于：用户往往会为旅行、约会、毕业、生日、纪念日、城市体验等重要场景认真准备造型，并由摄影师在真实环境中完成影像交付。

如果 Still 能在服务流程中低摩擦地记录：

```text
用户为什么拍
+ 想呈现什么状态
+ 穿了什么
+ 曾考虑哪些方案
+ 最终选择什么
+ 拍摄结果如何
+ 用户是否满意并愿意复用
```

那么 Still 获得的就不只是“漂亮照片”，而是可用于学习真实外观决策的结果记录。

长期闭环：

```text
Still 场景与服务需求
-> 服装 / 配饰 / 风格记录
-> Vibe 候选造型与试穿
-> 用户选择并真实拍摄
-> 拍后满意度与实际结果
-> 经独立授权的数据池
-> Vibe 推荐、评测与模型迭代
```

## 3. 数据资产定义：Appearance Outcome Record

未来最小有效数据单元暂称 `AppearanceOutcomeRecord`（外观结果记录）。它不是单张图片，而是一组有上下文、有来源、有授权范围的记录。

### 3.1 建议字段

| 数据层 | 示例字段 | 主要价值 |
| --- | --- | --- |
| 主体与授权 | `subject_id`、年龄段、授权版本、授权范围、授权时间、撤回状态 | 合规、追踪和删除 |
| 场景意图 | 城市、场景类型、拍摄目的、日期类别、天气类别、同行关系、预算区间 | 场景推荐与研究控制变量 |
| 外观目标 | 松弛、正式、甜、酷、干净、复古、照片冲击力、日常可复用等 | 把模糊审美变成可学习目标 |
| 服装信息 | 单品 ID、品类、层次、版型、长度、面料表现、颜色、图案、配饰 | Vibe 衣橱、推荐和试穿输入 |
| 候选与选择 | 候选造型、最终选择、拒绝项、拒绝原因 | 正样本、负样本和偏好学习 |
| 拍摄条件 | 地点、光线类别、姿态、镜头/构图类别、摄影师风格、修图强度 | 区分造型效果与摄影条件 |
| 结果反馈 | 最喜欢的照片、满意度、是否愿意日常复用、是否复约/推荐 | 训练目标与真实结果校验 |
| 数据派生 | 服装分割、姿态、场景标签、图像嵌入、质量标记 | 降低原图访问范围 |

### 3.2 为什么必须记录候选与拒绝

只有最终照片会形成严重的正样本偏差。它只能说明“这一套被拍下来了”，无法说明：

- 用户是否曾拒绝其他方案；
- 是服装好看，还是摄影师、光线、姿态和修图掩盖了问题；
- 该造型是否只适合出片，而不适合日常生活；
- 用户是否真正喜欢，还是只是完成了订单；
- 用户没有选择某套衣服的真实原因。

因此，未来推荐训练优先记录“少量候选 + 用户选择 + 拒绝原因”，不以无尽图片流代替有效标签。

## 4. Still 数据对 Vibe 的不同用途

### 4.1 推荐系统

Still 最有价值的推荐信号是：

- 场景与造型的匹配关系；
- 用户在多个候选之间的真实选择；
- 服装进入真实地点、天气和活动后的结果；
- 用户对“适合拍照”和“适合生活”的区分；
- 拍后满意、复约、收藏、分享或再次使用等结果。

推荐系统不应只学习流行审美，还要逐步回答 Vibe 的三层问题：

```text
Can wear：大概率能否穿、尺码风险在哪里
Will look good：廓形、比例、层次与场景呈现是否合适
Will use often：是否能进入用户衣橱和真实生活
```

### 4.2 虚拟试穿评测

Still 原图可在授权后成为真实环境评测样本，用于观察：

- 身份和身体比例是否被生成结果保留；
- 服装颜色、图案、版型、长度和层次是否忠实；
- 姿态、手部、头发、包、鞋和配饰的遮挡是否合理；
- 专业摄影条件与普通用户照片之间是否存在明显域差异；
- Vibe 的试穿结果是否帮助用户减少想象落差。

### 4.3 虚拟试穿训练

Still 的普通客片不能自动成为可训练的 VTON 配对样本。若未来希望训练试穿模型，需要额外设计可选采集：

```text
经授权的基准人物图 / 当前 avatar
+ 对应商品图或服装实物图
+ 结构化服装属性
+ 明确的实际穿着结果
+ 姿态、分割、层次和对应关系
```

缺少商品对应和标准化输入时，Still 图片优先用于场景理解、推荐监督和真实评测，不宣称为高质量试穿训练对。

## 5. 数据域与访问隔离

未来至少分为四个逻辑数据域，不能用一个“同意用户协议”的字段全部代替。

| 数据域 | 内容 | 默认状态 | 访问范围 |
| --- | --- | --- | --- |
| Still 服务媒体库 | 原图、精修图、交付文件、订单必要信息 | 服务必需范围内启用 | 用户、授权摄影师、必要运营人员 |
| 用户个人化档案 | 仅服务该用户的偏好、历史选择和可复用资料 | 用户明确开启 | 用户本人和必要服务模块 |
| Vibe 通用模型池 | 经独立同意的图片、服装信息、结果反馈及派生数据 | 默认关闭 | 经批准的模型/数据人员 |
| 学术研究池 | 经研究项目独立同意并满足伦理审批的数据子集 | 默认关闭 | 指定研究团队，按项目审批 |

必要原则：

- 原图与业务数据库分离存储；
- 原图、派生特征和公开样例使用不同 ID 与权限；
- 每条训练数据保留来源、授权版本、处理历史和删除状态；
- 不在 Git 仓库、日志、测试包、演示账号或融资数据室放置用户原图；
- 第三方模型/API 只能在已披露和已授权的处理范围内使用；
- 能用服装裁剪、遮脸版本、标签或派生特征完成的任务，不扩大原始人脸访问；
- 去标识化不能被当作绝对匿名，仍需评估重识别风险。

## 6. 授权与权利链设计

### 6.1 用户侧四层授权

未来产品应区分：

1. **服务交付**：完成预约、拍摄、修图、交付和售后所必要的数据处理；
2. **仅为本人个性化**：长期偏好和历史资料只服务该用户；
3. **平台通用模型训练**：用于改进 Vibe/Still 的推荐、理解、生成或评测模型；
4. **学术研究与公开展示**：用于特定研究、论文、报告、项目页或公开样例。

通用模型训练和学术研究应当：

- 默认关闭，由用户主动选择；
- 说明数据类型、目的、使用方式、保存期限和接收方；
- 记录同意时间、界面版本、政策版本和授权范围；
- 提供撤回和删除申请入口；
- 不把拒绝通用训练与能否获得基础摄影服务强行绑定；
- 跨境传输、公开展示、敏感个人信息处理按适用法律另行确认；
- 明确说明撤回对未来使用、原始数据、派生数据和已完成模型版本的实际影响。

### 6.2 摄影师与其他权利人

用户的肖像/个人信息授权，与摄影师或创作者的作品权利不是同一件事。未来摄影师/服务方协议应分别明确：

- 平台为完成订单可使用哪些作品；
- 是否允许用于平台通用模型训练；
- 是否允许用于学术研究；
- 是否允许公开展示、营销或融资演示；
- 原片、精修、预设、素材和第三方元素的权利边界；
- 授权期限、地域、撤回/终止和历史版本处理方式。

涉及模特、同行人、路人、品牌商品图、场地方或其他第三方内容时，需要单独判断权利来源，不能仅依靠摄影师或下单用户的一次授权覆盖全部主体。

### 6.3 法务与伦理审查

正式落地前由熟悉个人信息、肖像、平台服务和生成式 AI 的律师审阅：

- 用户服务协议；
- 隐私政策和敏感个人信息处理说明；
- 模型训练单独同意；
- 摄影师/创作者协议；
- 数据跨境和第三方处理条款；
- 删除、撤回、投诉和数据安全事件流程。

若数据进入 USYD 课程、Research Pathway、论文或其他人类参与者研究，应在收集研究数据前与导师确认 Human Research Ethics、研究数据管理、商业数据访问、发表权和 IP 安排。商业授权不能自动替代大学伦理审批，大学研究同意也不能反向覆盖商业模型训练。

## 7. 上线后的分阶段路线

### 阶段 0：当前版本——只保留文档

状态：当前。

行动：

- 本文进入 `docs/` 作为延后参考；
- 不修改 App、数据库、协议、媒体存储或数据流程；
- 不把该计划加入当前 P0/P1 发布阻塞项；
- Still 继续完成首城交易与服务闭环。

退出条件：真实预约、支付、履约、交付、售后和反馈均可运行并可追溯。

### 阶段 1：上线后——先验证业务和数据可用性

启动建议：达到现有运营手册中的可复用验证门槛，例如约 30 笔完成付费订单、形成连续订单趋势，并确认服务链路稳定。

只做：

- 复盘订单里目前已经自然产生哪些场景、服装和反馈信息；
- 用人工方式验证字段是否真的有运营价值；
- 观察用户是否愿意补充少量造型和满意度信息；
- 检查摄影师作品与用户照片权利链；
- 形成数据保护影响评估草案和法务问题清单。

暂不做：训练模型、批量图片理解、自动人脸分析和跨境研究传输。

### 阶段 2：结构化反馈试点——不训练原图

启动条件：业务稳定、法务文本和数据架构通过内部审查。

可试点：

- 拍摄目的、场景、想要的状态和参考风格；
- 少量服装结构标签；
- 用户最喜欢的交付图；
- 满意度、复用意愿和拒绝原因；
- 授权管理中心和数据来源记录；
- 基于结构化数据的规则推荐或轻量统计分析。

成功标准：字段完整率、用户填写负担、反馈质量和运营价值达到可接受水平，且撤回、删除和权限流程可执行。

### 阶段 3：Vibe 数据联动与小规模模型试点

启动条件：积累一批完整、经授权、可追溯且跨场景的数据；推荐问题和非 AI 基线已经定义。

可试点：

- Still 场景记录与 Vibe 造型候选关联；
- 用户选择/拒绝作为推荐反馈；
- 图像和结构化服装特征的联合表示；
- 只在授权子集上进行离线实验；
- 与规则、流行度、通用 embedding 等基线比较；
- 优先评估推荐质量、解释性和不确定性，不先宣传“大模型壁垒”。

### 阶段 4：USYD 研究路径

启动条件：已入学并建立本校导师关系；研究问题、数据权限、伦理审批和 IP 安排明确。

研究主线建议：

> 面向真实生活场景的、具不确定性校准的个性化服装外观决策系统。

产品与研究分工：

- Still：提供经授权的真实场景、选择过程和结果反馈；
- Vibe：提供衣橱、商品、试穿、候选造型和决策界面；
- 研究：验证结构化服装语义、场景上下文和不确定性是否改善真实外观决策；
- 公开许可数据：承担早期方法基线和可复现实验；
- Still 授权子集：承担生态有效性评测，不让论文进度依赖平台先形成巨大规模。

## 8. 研究问题与可发表证据

未来研究不以“拥有很多照片”作为贡献，而需要可检验问题。

### 8.1 候选研究问题

1. 结构化服装属性是否能提高多单品试穿的服装忠实度和层次稳定性？
2. 加入衣橱、场景与用户目标后，推荐是否优于只看商品图或流行度的基线？
3. 模型能否区分“适合拍照”和“适合日常使用”？
4. 在证据不足时，置信度提示、追问或拒答是否减少错误决策？
5. 摄影师、光线、姿态与修图对审美标签造成多大混杂，如何控制？
6. Still 的真实结果反馈是否能改善 Vibe 的长期个性化，而不是只提高一次点击？

### 8.2 证据层级

```text
离线指标
-> 服装专家/摄影师评测
-> 用户候选选择实验
-> 真实场景满意度和复用意愿
-> 长期复约、衣橱利用或购买决策结果
```

前一层未成立时，不直接跳到“降低退货率”“理解用户生活”或“世界模型”等更大结论。

## 9. 主要偏差与风险

| 风险 | 表现 | 未来控制方式 |
| --- | --- | --- |
| 精选偏差 | 只有用户愿意保存和发布的好照片 | 保留候选、拒绝和拍后评价 |
| 摄影条件混杂 | 光线、姿态、摄影师和修图影响外观 | 记录条件并做分层评测 |
| 场景偏差 | 旅拍/纪念场景不等于日常穿搭 | 单独建模拍照适配与生活适配 |
| 人群偏差 | 首城、特定年龄和审美人群过度集中 | 明确适用范围，扩张后再验证 |
| 标签噪声 | 完成订单不代表真满意 | 使用最爱图、评分、复用和拒绝原因 |
| 尺码误判 | 精修照片无法证明真实合身 | 只输出风险，不从图片推断绝对尺码 |
| 隐私与重识别 | 人脸、身体、地点和同行关系高度敏感 | 数据最小化、分层权限、独立同意和删除 |
| 权利不清 | 用户、摄影师、场地、品牌和同行人权利交叉 | 逐类合同与来源记录 |
| 学术/商业冲突 | 发表、保密、IP 和用户授权范围不一致 | 入学后在研究前书面确认 |

- [ ] 模型卡、数据卡和版本回滚。

## 11. 启动 / 暂停判断

只有同时满足以下条件，才建议从规划进入实施：

- Still 已证明真实交易和履约价值；
- 数据字段能改善运营或用户决策，而不是为了“以后也许有用”；
- 用户和摄影师授权可以清晰取得、记录、撤回和执行删除；
- 原图存储、权限、第三方处理和安全事件机制可承担相应风险；
- Vibe 已有明确问题、基线和评测方法；
- 研究合作已确认伦理、数据、发表和 IP 边界；
- 该方向不会挤压 PTE、USYD 高 WAM 和主研究成果。

出现以下情况则暂停：

- Still 自身服务价值和订单闭环尚未成立；
- 用户只愿意获得摄影服务，不愿补充必要反馈；
- 权利链、跨境、删除或第三方模型处理无法解释清楚；
- 只能积累漂亮图片，却无法获得商品、场景、选择和结果对应；
- 研究题目需要等平台大规模裂变后才能开始；
- 数据计划显著增加首发成本、延迟上线或损害用户信任。
