# Still App Store 最短上架路线

本文档服务于当前已确认目标：先发布不含支付的 `Store Lite 1.0`，取得公开 App Store 页面后，再申请支付渠道并开发收费运营 `v1.1`。

节点状态和依赖以 [Still 双平台发布 Roadmap](./DUAL_PLATFORM_RELEASE_ROADMAP.md) 为唯一事实源；本文只说明首审产品范围、实施顺序和审核材料。

## 当前固定决策

- 首次上架不是完整双边交易平台，而是“精选摄影师浏览与真实预约申请”。
- 当前版本不提供 App 内付款，不出现支付、定金、退款、钱包、提现、佣金或结算状态。
- 获得公开 App Store URL 后，才启动支付渠道审核和商业 `v1.1`。
- 首审采用消费者专用构建入口，未完成能力从构建、路由、深链、导航和审核文案中排除，不能只用运行时开关隐藏。
- 摄影师与内容由平台运营预审和维护；首审不开放摄影师移动端入驻、投稿或收益工作台。
- 地点仅使用用户输入的城市和地址文字；首审不申请定位权限，不接完整地图 SDK、POI、附近或路线时间。
- 真实账号、真实预约、客服举报、账号删除、生产后端和审核期间在线不能后置。

## Store Lite 用户闭环

```text
游客浏览精选作品与摄影师
-> 搜索并查看摄影师详情
-> 登录后填写摄影师、日期、时间、城市/地址和需求
-> 提交真实预约申请
-> 平台受保护运营入口联系摄影师后确认/拒绝
-> 用户查看、刷新或取消申请
-> 必要时联系客服、举报或删除账号
```

这条闭环必须真实可履约。只有图片和电话号码的黄页不够；用户提交后，服务端和受保护运营入口必须能看到申请，由平台线下联系摄影师并把确认结果写回。确认后向用户展示经过审核的到店说明和平台客服，不在首审暴露摄影师私人电话。

## 首审保留范围

- 游客浏览真实精选作品
- 找摄影师、搜索和手动筛选
- 作品详情和摄影师详情
- 消费者手机号注册/登录与会话恢复
- 结构化预约申请
- 预约列表、详情、刷新和取消
- 内容/摄影师举报
- 客服申请
- 隐私政策、用户协议、数据权利申请和真实账号删除
- 我的预约、设置和退出登录

建议底栏固定为：

```text
发现 / 找摄影师 / 预约 / 我的
```

## 首审排除范围

- Checkout、支付、定金、退款、钱包、提现和结算
- 摄影师移动端、摄影师自助入驻、投稿和收益页面
- 普通用户公开主页、发帖、评论、关注流和排行榜
- 泛私信；如预约履约聊天未形成完整举报/屏蔽闭环，也从首审排除
- 用户媒体上传、参考图、视频和 Live Photo 上传
- 主动定位、附近频道、地图 SDK、POI、服务距离和路程时间
- 妆造商家、组合订单、双档期和商家 SaaS
- Push、推荐算法、Agent、Vibe、AI、小程序和 B 端业务

被排除能力不得留下“即将上线”、不可点击按钮、假成功、假空状态或可以通过深链访问的页面。

## 模块推进顺序

每个模块完成后运行最小相关验证并创建本地检查点；不自动推送 GitHub。

### 第 0 阶段：建立 Store Lite 专用构建

1. 新建 Store Lite 移动入口或等价的编译期路由白名单。
2. 注册和登录固定为消费者身份。
3. 移除摄影师端、Admin、Checkout、社区、泛私信、定位和上传路由。
4. 删除支付、退款和资金状态文案。
5. 增加构建产物检查，禁止被排除路由和支付配置进入 iOS 包。

完成标准：导航、返回栈和深链只能进入 Store Lite 白名单；生产包内无 mock 支付和测试角色。

### 第 1 阶段：生产环境和真实内容

1. 正式域名与 HTTPS API。
2. PostgreSQL 16 生产数据库与最小权限账号。
3. 自动备份、健康检查、request ID 和脱敏日志。
4. 平台预审的真实摄影师和稳定 HTTPS 作品。
5. 记录作品版权、肖像授权和下架负责人。
6. 生产 CORS 必须精确包含 iOS 容器来源 `capacitor://localhost`；其他来源只允许实际部署的 HTTPS Web/Admin origin，不使用通配符。

首审不需要开放客户端媒体上传，但真实内容不能来自临时 URL、data URL、Mock 或开发机。

完成标准：首页、搜索和详情全部来自生产数据；API 不可用时明确失败并可重试。

### 第 2 阶段：最小真实账号

1. 优先完成现有手机号验证码方案。
2. 游客可浏览，仅提交或管理预约时要求登录。
3. Session、退出、过期和重新登录来自服务端事实源。
4. 准备长期有效的消费者审核账号和预置内容/预约状态。
5. App 内账号删除调用真实 API，不能只写 localStorage、发邮件或显示假提交。
6. 准备无管理权限、无真实隐私数据、服务端受限且可撤销/轮换的审核主备账号；凭据只填写在 App Store Connect 的 App Review Information/Notes，不能进入二进制或公开文档。
7. 在固定首发 territory 前确认登录可用性：若仅支持 +86，须与目标用户和元数据一致；否则先补 E.164 或经批准的替代登录。

若短信外部审批长期无法完成，再单独评估 Sign in with Apple；不要为了赶首审同时维护两套新登录。

完成标准：审核员不依赖本地验证码即可登录；真实首发用户有可用登录方式；重启和换设备可恢复；删除申请可查询和处理。

### 第 3 阶段：真实预约申请

最小字段：

```text
摄影师 ID
日期
时间段
城市
地址文字
需求说明
必要的联系信息（按隐私政策最小化收集）
```

最小状态：

```text
submitted
confirmed
declined
cancelled
```

状态只表达预约处理结果，不表达资金。客户端不能提交或伪造 `paid`、`escrowed`、`refunding`、`settled` 等值。

用户提交前和结果页必须明确显示：“提交申请不等于服务已确认，当前版本不发生扣款。”Store Lite 由受保护运营入口联系摄影师后处理；确认时保存用户可见的时间、城市/地址文字、到店说明和平台客服渠道。申请列表/详情返回 `updatedAt`，支持下拉或按钮手动刷新；首版不依赖 Push。

完成标准：用户提交后，受保护运营入口能处理；用户和运营只能访问各自授权资源；重复提交、确认、拒绝和取消幂等；跨设备可恢复。审核账号预置 `submitted`、`confirmed`、`declined`、`cancelled` 样例，审核不依赖等待真实摄影师即时回复。

### 第 4 阶段：合规和最小运营

必须具备：

- 正式隐私政策和用户协议 URL
- App Store Connect App Privacy
- 客服入口和可用联系方式
- 内容/摄影师举报
- 最小下架、封禁和审计能力
- 账号删除与数据权利申请；自动导出是否首审实现以正式合规结论为准
- 实际启用权限的用途文案

首审不使用定位、相机、相册或麦克风时，应从 Info.plist、隐私清单和代码路径中移除对应权限请求。

完成标准：政策 URL 可从公网和真机访问；举报、客服、删除和数据权利申请真实落库；用户举报后可立即隐藏对应摄影师及内容，运营复核后可下架或封禁；App Privacy 与代码和第三方 SDK 一致。

### 第 5 阶段：移动端 QA

覆盖：

1. iPhone 小屏、安全区和键盘
2. 冷启动、前后台和重新登录
3. 弱网、断网、超时、401、403、404、500 和坏响应
4. 空状态、加载态、重复点击和重试
5. 预约提交、确认/拒绝、取消和跨设备刷新
6. 举报、客服、删除账号，以及提交并查询数据访问/副本请求
7. 深链和返回栈不能进入被排除页面
8. 生产 API 失败不能显示 mock、seed 或虚假成功
9. 受保护运营入口可处理申请，确认后用户能看到到店说明和平台客服
10. 审核账号可直接查看四种预置预约状态

完成标准：Store Lite 真机主流程连续回归通过，无白屏、崩溃、阻断或假成功。

### 第 6 阶段：签名与 TestFlight

1. Apple Developer 公司账号、正式 Team 和 Bundle ID。
2. 使用当前 Apple 要求的 Xcode 和 iOS SDK。
3. Store Lite Release Archive。
4. 上传 App Store Connect 并安装 TestFlight。
5. 核对图标、版本号、build、权限、隐私清单和生产 API。
6. 使用审核账号完成完整预约闭环。

完成标准：TestFlight 可安装；构建可追溯到完整 Git SHA；包内没有支付 SDK/商户配置、测试角色或被排除路由。

### 第 7 阶段：App Store 提交

准备：

- App 名称、Bundle ID、SKU、图标和 iPhone 截图
- 描述、关键词、分类和年龄分级
- 隐私政策 URL、用户协议 URL、支持 URL 和联系方式
- App Privacy 和出口合规回答
- 审核账号、操作路径和后端在线说明
- 内容版权与肖像授权记录
- 首发 territory 与中国大陆备案/限制结论

审核说明统一口径：

```text
当前版本用于浏览平台审核的摄影作品与摄影师，并提交线下摄影服务预约申请。
当前版本不提供 App 内付款、数字内容购买、定金、退款、钱包或结算功能。
```

完成标准：提交版本、TestFlight build、审核材料、生产部署和 release SHA 一致。

## 中国大陆发行边界

- 首发包含中国大陆：提交前完成适用的 ICP、APP 备案或其他资质，或取得正式“不适用”结论。
- 备案流程必须先取得公开链接：首发 territory 暂时排除中国大陆，取得页面后继续备案；备案完成前不得宣传为大陆已上线。
- 支付渠道是否接受非大陆 App Store 页面必须由 `EXT-FILING-1`/`EXT-PAY-1` 留下明确结论，不能假设。
- 若首发暂时排除中国大陆，必须同时核对 +86-only 登录是否与目标用户一致；审核测试账号不等于真实用户登录方案。

## 上架后的支付 v1.1

`INT-STORE-1` 记录公开 App Store URL 后，按以下顺序推进：

1. 使用公开页面申请支付商户和 App 支付权限。
2. 确认支付渠道、证书、回调域名和测试窗口。
3. 定稿支付说明、退款规则、资金状态和新增资质。
4. 服务端实现支付下单、签名、回调验签、幂等、状态查询、退款、重试和对账。
5. iOS 实现真实 App 支付、返回恢复、取消和失败处理。
6. 以新的 TestFlight build 完成小额支付和退款。
7. 重新提交 App Store 更新。

摄影属于 App 外履约的实体服务，后续可以采用获批的非 IAP 支付方式；这不代表首审版必须包含付款。

## 最短进度判断

已经具备：

- iOS/Capacitor 基础工程和早期真机基线
- 生产化 Feed、摄影师资料、作品和收藏服务端
- 集中鉴权、请求校验、错误码、限流和日志脱敏基础
- 订单 PostgreSQL 权威读取的主要实现
- Store Lite 独立消费者入口、编译期路由/模块白名单、无支付 UI 和生产 bundle 完整性守卫
- 真实预约申请、四状态、取消、客服/数据请求、举报与屏蔽的 PostgreSQL schema、API 和消费者页面
- 只处理预约、用户请求和内容举报的独立窄运营台；旧完整 Admin 不进入消费者包
- 生产发行配置、官方 API origin、测试角色、短信模式、功能开关和非 PostgreSQL 回退的失败关闭检查
- PostgreSQL 16 预约/合规 live audit 与 Store Lite 双前端构建已接入 CI，但尚未通过推送实际运行

当前最短链的主要缺口：

- 将当前本地检查点推送后，取得 PostgreSQL 16 live audit 和 Store Lite 双构建 CI 证据
- 部署云 PostgreSQL、正式 API 与窄运营台，启用 Store Lite 两个功能开关并完成备份/恢复和在线健康检查
- 腾讯短信真实发送、首次手机号登录、会话恢复，以及普通消费者审核主备账号
- 部署并批准隐私政策、用户协议和支持页；验证客服邮箱收件和值守
- 根据正式保留政策完成账号删除执行器、会话撤销、处理 SLA 和运营演练；当前仅已实现 App 内真实发起/查询/取消
- 预置真实授权作品、摄影师以及 submitted/confirmed/declined/cancelled 四类审核样例
- 明确首发 territory、+86 登录适用性和中国大陆 APP/ICP 备案路径
- 在 Mac 用干净提交重新构建并执行 Capacitor sync、原生 seal、Release Archive、真机 QA 和 TestFlight
- 准备 App Store Connect 元数据、截图、App Privacy、审核说明及最终提交

支付、完整地图、媒体上传、聊天、商家和 AI 不再进入首次上架关键路径。
