# Still 妆造商家冷启动合作与组合订单实施方案

> 状态：已确认的试点事实源
>
> 版本：1.0
>
> 更新日期：2026-08-20
>
> 适用范围：Still 首城冷启动中的摄影师＋妆造/服装商家合作
>
> 执行关系：技术实施以 [双平台发布 Roadmap](./DUAL_PLATFORM_RELEASE_ROADMAP.md) 的节点和依赖为准；本文件固定产品、运营和合作规则。历史讨论见 [组合交易构想备忘录](./IDEA_MERCHANT_PHOTOGRAPHER_COMPOSITE_BOOKING.md)。

## 1. 冷启动结论

Still 不建设一个新的摄影馆黄页，也不要求商家拆掉现有摄影套餐。首期只增加一条窄而清楚的交易路径：

> 用户先通过作品或摄影师完成审美选择，再按需给该次拍摄增加商家提供的妆造、服装服务。

对用户，它是一站式订单；对后台，它是由摄影和商家服务项组成的组合订单；对商家，它是一条不影响美团、抖音、线下和原有摄影套餐的增量渠道。

首批优先合作对象：

- 独立妆造、写真造型、汉服妆造和服装租赁门店；
- 已接受“只做妆造”或“只租服装”的写真馆、摄影馆；
- 有部分可用产能、愿意把服务内容和价格提前说清的门店；
- 决策链短，能够指定一名接单负责人和一个公开营业电话的门店。

首批不优先：

- 只出售摄影＋妆造强绑定套餐的门店；
- 旺季长期满负荷、没有增量服务能力的景区流水线店；
- 依赖现场强制加价或成交前长时间电话判断需求的高度定制服务；
- 无法保证用户实际获得页面所选摄影师的流水线门店。

## 2. 用户入口和页面关系

### 2.1 只保留两个主要搜索入口

- 找作品；
- 找摄影师。

不新增“找妆造商家”“找摄影馆”或“找拍摄方案”入口。拍摄方案是在用户选定服务后形成的订单方案，不是第三类搜索对象。

搜索商家名称时，结果仍然是与该商家存在真实、双方确认合作关系的摄影师。摄影师页需要明确区分：

- “某店店内摄影师”；
- “可搭配某店妆造与服装”。

冷启动阶段，一名摄影师最多展示零个或一个主要合作商家；一个商家可以关联多名摄影师。商家介绍摄影师不等于代替摄影师入驻、授权作品或承担摄影履约责任。

### 2.2 用户选择顺序

```text
找作品 / 找摄影师
→ 选择摄影师和拍摄时间
→ 填写结构化需求
→ 选择仅摄影 / 摄影＋妆造 / 摄影＋妆造＋服装
→ 选择期望妆造时间
→ 查看服务清单和锁定总价
→ 一次预付款
→ 摄影师与商家并行接单
→ 组合订单正式确认
→ 订单页开放商家营业电话
→ 线下履约、交付和分项售后
```

“一站式”不等于替商家出售未知档期。用户提交的是明确时间请求，商家接受后该时间才正式成立。

## 3. 服务、价格和需求单

### 3.1 摄影服务

摄影师为可选择的结构化需求模块预设单位价格，包括但不限于拍摄时长、人数、精修数量、额外交付和服务范围。需求单按照用户选项叠加，服务端计算摄影服务价格。

摄影师收到订单后只做两件事：接受，或因无法满足时间/需求而拒绝。摄影师不得在接单时重写已经展示给用户的价格。

### 3.2 商家服务

商家首期只上架 1—3 个边界清楚的固定价核心套餐。每个套餐至少明确：

- 套餐名称和适用场景；
- 固定价格和标准时长；
- 适用人数；
- 妆容、发型、服装及配件包含范围；
- 明确不包含的内容和可选固定价加项；
- 准备事项、服装尺码和归还规则；
- 门店地址、营业时间和公开营业电话。

商家自行定价，Still 不擅自修改。套餐变更只影响新订单；已经下单的订单保存不可变的价格、内容、版本和时间快照。

服装押金不进入 Still 订单。商家必须在下单前公开押金、归还、超时和损坏规则；发生争议时由一方在订单内发起客服处理，不允许把未说明费用强制加入平台订单。

### 3.3 用户看到的订单

用户只看到：

- 一份服务清单；
- 一个总价；
- 一次支付；
- 一个订单状态；
- 一个售后入口。

订单内必须清楚标明摄影服务和妆造/服装服务分别由谁提供，但不向用户暴露内部账本和分账操作。

后台以服务项分别保存提供方、套餐版本、价格、时间、接单、履约、退款、佣金和结算状态。妆造不得作为普通 `order_extra` 塞入摄影订单。

## 4. 时间、接单和电话规则

### 4.1 妆造时间推荐

当前 App 只通过地图 URI 调起外部地图，无法从 URI 获得路线耗时。MVP 不为了这一功能接入路线 API，也不承诺精确到达时间。

系统按商家套餐时长和用户选择的交通缓冲生成推荐时间：

| 场景 | 默认缓冲 |
| --- | ---: |
| 同一地点或同楼 | 15 分钟 |
| 附近步行 | 30 分钟 |
| 需要乘车 | 60 分钟 |
| 路线不确定 | 90 分钟 |

用户可以调整期望妆造时间。系统只禁止明显无法在拍摄前完成的组合；其余通过“衔接宽松/推荐/偏紧”提示风险，不替用户保证实际交通。

### 4.2 并行接单

用户确认服务清单后一次预付款，摄影师和商家并行收到同一组合订单中属于自己的服务项：

- 摄影师普通订单：4 个有效接单小时；默认接单时段 09:00—22:00，摄影师可在规则范围内配置；时段外暂停计时；
- 商家普通订单：2 个有效营业小时，以门店已公布营业时间计时；
- 距离最早服务不足 24 小时：只向主动开启“紧急可接单”的服务方发单，确认时限 30 分钟。

接单前服务方可以拒绝；接单后即承诺订单中的时间、价格和服务范围。拒绝必须选择原因，超时等同拒绝并释放相关临时占用。

分支规则：

- 摄影师拒绝或超时：主服务无法成立，整单取消并原路全额退款；
- 商家拒绝或超时：用户可保留摄影并退回商家服务金额，或取消整单并全额退款；
- 用户收到商家拒绝通知后，普通订单有 2 个有效小时作选择，紧急订单有 30 分钟；未选择则默认取消整单并全额退款。

### 4.3 电话显示

成交前绝对不显示商家电话，也不要求用户先电话预约。只有摄影师和商家都接受、组合订单正式确认后，订单页才显示商家公开营业电话。

电话只用于：

- 临近服务时间再次核对；
- 询问路线、到店方式和准备事项；
- 沟通服装尺码、头发状态等已成交服务细节。

用户不打电话不影响预约效力。电话中不得改价、要求线下支付或绕过 Still 取消订单；时间变化必须回到订单内由受影响方确认。

## 5. 迟到、取消、异常和改期

### 5.1 默认正常履约

服务时间经过后默认按正常流程推进。系统不按迟到分钟数自动罚款，不因为距离拍摄时间接近而静默取消，也不把提醒当作异常证据。

现场允许像理发、美甲一样由双方协调顺延、调整次序或在同意的范围内压缩服务。只有一方主动发起“服务异常/申请取消”后，平台才进入归责流程。

### 5.2 取消和归责矩阵

| 情况 | 处理 |
| --- | --- |
| 摄影师或商家尚未全部接受 | 取消相关未确认交易，全额退款 |
| 距最早服务超过 24 小时，用户取消 | 全额退款 |
| 距最早服务不足 24 小时，且确认由用户迟到/失约导致 | 退还受影响服务项 80%的服务价值；20%作为全额归服务方的非计佣档期补偿 |
| 服务方原因无法履约 | 受影响服务项全额退款，服务方不结算；摄影师为主服务方时整单取消 |
| 双方协商一致或无法明确归责 | 全额退款 |
| 对事实或责任存在争议 | 客服接入，按证据处理 |

20%只适用于已经确认且确有用户责任的受影响服务项，不自动扩展到未受影响服务。该 20% 全额作为非计佣档期补偿进入受影响服务方应结金额，不再收取 8% 平台佣金。

### 5.3 改期

原则是：能不改的就不改，只重新确认受影响服务项。

- 只调整妆造时间：用户和商家确认，摄影时间不变；
- 同日拍摄向后延迟，且妆造时间、套餐、地点、服装归还或商家现场安排不受影响：只需用户和摄影师确认，商家收到通知但无需重新接单；
- 拍摄提前、跨日、地点变化，或影响妆造/服装服务：用户、摄影师和受影响商家重新确认；
- 同一服务方、同一套餐内容的改期保持原锁定价格；用户主动改变时长、套餐或服务内容时按差价重新确认。

## 6. 佣金、结算和退款资金规则

### 6.1 试点商务数字

- 试点周期：首笔真实组合订单起 30 个自然日，或 10 笔已完成组合订单，先到为准；
- 入驻费、软件费、年费：0 元；
- 摄影与商家服务项平台佣金：分别按各自服务项的计佣基数收取 8%；
- 支付通道手续费和平台主动优惠：MVP 由 Still 承担；
- 试点非独家，不要求商家预留 Still 专属库存；
- 试点结束后，费率和范围只有经书面确认才改变，不自动涨价或转为收费软件。

金额统一按以下口径计算：

1. `计价金额 = 锁定原价－服务方明确承担的优惠`；平台优惠券不降低计价金额；
2. `用户应付 = 计价金额－分摊到该服务项的平台优惠`；平台补足这部分优惠；
3. `计佣基数 = 计价金额－按服务价值计算的退款－非计佣档期补偿`；
4. `服务方应结金额 = 计佣基数 × 92%＋非计佣档期补偿`；
5. 支付通道手续费不从服务方应结金额中扣除。

固定验收样例：

- 正常履约 100 元：平台佣金 8 元，服务方应结 92 元；
- 使用 10 元平台券：用户支付 90 元、Still 补足 10 元，服务方仍应结 92 元；
- 用户责任取消且按 80%/20%处理：退还 80 元服务价值，服务方获得 20 元非计佣档期补偿，平台佣金 0 元。

平台优惠在支付时按服务项留下不可变分摊快照。发生退款时，优惠券按该服务项退款比例退回；原券失效则等值补发，现金退款不得超过该服务项用户实际支付金额。该数字和公式需要在 `WIN-SETTLE-1` 中成为服务端版本化规则，清理现有前后端 8%、10%、15% 的不一致；客户端不得自行计算最终佣金或退款。

### 6.2 服务项结算

用户侧仍是一个订单，但结算以服务项为单位：

1. 服务方标记服务完成后，用户主动确认即可让该服务项进入可结算，也可以发起异常；
2. 若用户未操作，服务计划结束后 72 小时且无异常，该服务项自动进入可结算；
3. 每个服务项按计价金额、平台优惠分摊、退款、8%佣金和非计佣补偿形成独立应结算金额；
4. 商家妆造服务完成后不等待摄影师后期交付；摄影服务按其交付与完成规则进入结算；
5. 原则上只冻结有争议的服务项；只有支付异常、责任无法拆分或整单欺诈风险时才冻结整单；
6. 平台按经支付机构、合规和财务确认的方案处理资金，不能在未取得相应能力时对外使用不准确的“资金托管”表述。

平台先行退款或赔付后，可依据已通知、可申诉、证据可审计的裁定，从责任方未结算金额中扣回；不足部分进入人工追偿，不允许形成不可解释的负余额。

## 7. 商家端最小产品

冷启动采用同一 Still 代码库中的轻量移动 Web 商家工作台，不开发独立商家 App，也不安装本地 SaaS。商家由运营协助入驻，只需要：

- 待接单：查看用户已预付的明确时间、人数、套餐和必要需求，接受或拒绝；
- 已确认订单：查看服务清单、时间、到店信息和履约操作；
- 套餐管理：维护 1—3 个固定套餐并提交审核；
- 门店设置：营业时间、地址、公开营业电话和紧急接单开关。

MVP 不做：

- 员工、工位和全渠道库存管理；
- 美团、抖音或门店收银系统同步；
- Still 专属保证名额；
- 自动判断现场等待、迟到或商家并发能力；
- 成交前电话咨询链路。

## 8. 商家合作定位和准入

对商家不使用“解绑摄影馆和摄影师”。统一表达为：

> 不影响您现有摄影套餐，新增一条面向“已经选好摄影师、仍需要妆造或服装”的增量服务渠道。

一句话价值主张：

> Still 不要求门店更换现有系统、预留专属库存或放弃原有摄影套餐；门店只需上架 1—3 个自己定价的标准妆造/服装服务，对时间和需求明确、已经完成预付款的订单逐笔决定是否承接。

商家准入必须满足：

- 提供真实经营主体或身份资料、门店地址、营业时间和公开营业电话；
- 套餐价格、时长、适用人数、包含和不包含内容清楚；
- 接受成交后锁价，不强制线下支付或隐性加价；
- 能在有效营业时间内处理订单，接单后按确认内容履约；
- 接受平台取消、退款、证据留存、申诉和争议处理规则；
- 服装相关押金、尺码、归还和损坏规则提前公开；
- 关联摄影师的合作关系由双方确认。

Still 对商家承诺：

- 接单前展示判断所需的结构化需求；
- 成交前不公开商家电话；
- 不擅自修改商家服务价格；
- 不要求专属名额、系统迁移或渠道独家；
- 用户先预付，订单、退款和责任记录在同一入口；
- 试点阶段协助整理套餐、录入资料和完成模拟订单。

Still 不承诺订单量、收入、稳定曝光、绝对准时、准确路程、无投诉或当前已经具备实时库存。

## 9. 30 天受控试点

### 9.1 试点范围

- 1—3 家首批门店，每家 1—3 个标准套餐；
- 每家一个公开营业电话和一名订单负责人；
- 少量双方确认的真实合作摄影师；
- 不独家、不装本地软件、不预留库存；Still 不同步或接入美团、抖音等外部平台订单与库存，商家原渠道照常使用；
- 每家先跑一笔模拟订单；模拟通过只是必要条件，支付、部分退款、分项结算、权限、合规和财务闸门全部通过后才开放真实受控订单；
- 商家可暂停新订单，但不得影响已确认订单。

### 9.2 成功和停止条件

每周至少记录：

- 发单量、商家接受率、双方平均响应时间；
- 组合订单确认率、保留摄影比例、完成率和取消率；
- 用户实际等待、商家延误、迟到和争议；
- 商家新增实收金额和每单额外操作时间；
- 是否发生强制加价、电话二次预约、线下绕单或责任不清；
- 用户满意度、商家继续意愿和套餐扩展意愿。

出现以下任一情况，暂停扩大：

- 真实支付、部分退款、分项结算或权限隔离未通过验收；
- 商家无法稳定承诺已接受的明确时间；
- 电话在正式确认前泄露；
- 组合订单纠纷明显高于单摄影订单且规则无法解释；
- 商家新增收入不足以覆盖操作成本；
- Still 需要靠人工改价、伪造库存或线下收款维持流程。

## 10. 内容、关注和作品边界

- 普通用户主页可展示个人介绍和其主动公开的 Still 真实订单作品；不能上传站外摄影、日常或无关内容；
- 关注功能保留，用于追踪拍摄足迹和进入“拍同款”；
- 摄影师可为冷启动发布站外作品，但必须标注“摄影师作品集”，与 Still 订单作品分区；
- 一张订单作品在后台可以关联用户、摄影师、妆造方、订单和服务项，首页仍以作品和摄影师为主，不平铺所有关系；
- 评论、社交私信、转发链和排行榜不随本试点自动开放；交易咨询与客服沟通保留；
- 订单完成后可生成九张独立图片、九宫格、文案、话题、署名、地点和 BGM 搜索关键词，但不建设完整修图或剪辑软件。

## 11. Agent 长期路线

Agent 后置并内置于产品，不作为首页独立入口或当前商家试点卖点。首期能力只包括：

- 理解自然语言；
- 拆解拍摄需求；
- 填写与手动菜单相同的结构化字段；
- 提醒用户检查缺失或互相冲突的选项。

菜单始终保留，用户可以查看、修改和删除 Agent 填写的任何字段。当前商家没有实时库存，因此 Agent 最多生成期望妆造时间和可确认的订单草稿，不能承诺预约成功。

Agent 不得自动付款、改价、取消、替服务方接单或绕过用户最终确认。Vibe、审美指导和智能排期只有在真实供给、服务项、库存、偏好和履约数据成熟后另行立项。

长期领域模型保持模块化：摄影、妆造、服装和未来场地都是可组合服务项；摄影师和商家是兼容关系，不把商家所有权硬编码到摄影师账户中。

## 12. 实施顺序和发布边界

1. 固定合作规则、商务数字、合规措辞、Word/PPT和 30 天试点确认单；
2. 建立商家、固定套餐、合作关系和订单服务项领域骨架，功能开关默认关闭；
3. 上线商家供给和“搜商家名仍找摄影师”的只读展示；
4. 在真实支付、部分退款和结算基础完成后，实现一次预付、并行接单和分支退款；
5. 完成用户、摄影师、商家和 Admin 的跨角色、跨设备、金额守恒和电话脱敏验收；
6. 每家模拟订单通过，且支付、部分退款、分项结算、权限、合规、财务与跨角色验收全部通过后，才开放少量真实受控订单；
7. 以真实数据决定继续、调整或停止，不以注册量和页面数量代替验证。

`INT-COMBO-1` 完成前禁止真实组合支付。商家相关功能必须由默认关闭的功能开关控制；关闭后不能影响当前纯摄影订单、P0 Release Candidate 或 App Store 主流程。
