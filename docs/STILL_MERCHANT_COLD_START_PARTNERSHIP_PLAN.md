# Still 妆造供给冷启动合作与组合订单实施方案

> 状态：已确认产品原则；对外合作材料待同步
>
> 版本：1.1
>
> 更新日期：2026-08-25
>
> 适用范围：Still 首城冷启动中的摄影师＋个人妆造师/妆造门店合作
>
> 执行关系：技术实施以 [双平台发布 Roadmap](./DUAL_PLATFORM_RELEASE_ROADMAP.md) 的节点和依赖为准；本文件固定产品、运营和合作规则。历史讨论见 [组合交易构想备忘录](./IDEA_MERCHANT_PHOTOGRAPHER_COMPOSITE_BOOKING.md)。

## 1. 冷启动结论

Still 不建设一个新的妆造黄页，也不要求门店拆掉现有摄影套餐。首期只增加一条窄而清楚的交易路径：

> 用户先通过作品或摄影师完成审美选择，再在需求卡内按需增加个人妆造师或妆造门店提供的妆造服务。

对用户，它是一站式订单；对后台，它是由摄影和妆造服务项组成的组合订单；对个人妆造师，它是围绕上门服务的新增订单渠道；对门店，它是一条不影响美团、抖音、线下和原有摄影套餐的增量渠道。

产品内统一使用“妆造”，基础含义为“妆面＋发型或基础整体造型”。服装租赁、配饰、复杂造型、多人妆造和全程跟妆必须明确包含范围或单独计价。

首批优先合作对象：

- 能提供本人真实作品、明确服务区域与固定套餐的个人妆造师；
- 可前往用户家、酒店等暂居地上门履约，并愿意在平台内确认时间的个人妆造师；
- 独立妆造、写真造型、汉服妆造和服装租赁门店；
- 已接受“只做妆造”或“只租服装”的写真馆、摄影馆；
- 有部分可用产能、愿意把服务内容和价格提前说清的门店；
- 决策链短，能够指定一名接单负责人和一个公开营业电话的门店。

首批不优先：

- 只出售摄影＋妆造强绑定套餐的门店；
- 旺季长期满负荷、没有增量服务能力的景区流水线店；
- 依赖现场强制加价或成交前长时间电话判断需求的高度定制服务；
- 无法保证用户实际获得页面所选摄影师的流水线门店。
- 无法证明作品由本人或实际履约团队完成的个人或门店。

## 2. 用户入口和页面关系

### 2.1 只保留两个主要搜索入口

- 找作品；
- 找摄影师。

不新增“找妆造”“找妆造商家”“找摄影馆”或“找拍摄方案”一级入口。拍摄方案是在用户选定服务后形成的订单方案，妆造是需求卡内的可选服务，不是第三类搜索对象。

搜索门店名称时，结果仍然是与该门店存在真实、双方确认合作关系的摄影师。摄影师页需要明确区分：

- “某店店内摄影师”；
- “可搭配某店妆造与服装”。

冷启动阶段，一名摄影师最多展示零个或一个主要合作妆造方；一个个人妆造师或门店可以关联多名摄影师。妆造方介绍摄影师不等于代替摄影师入驻、授权作品或承担摄影履约责任。

### 2.2 用户选择顺序

```text
找作品 / 找摄影师
→ 选择摄影师和拍摄时间
→ 需求卡自动带入极简推荐方案
→ 确认时间、拍摄地和人数
→ 选择不需要 / 添加妆造
→ 从平台推荐 / 个人妆造师 / 妆造门店中快速选择
→ 查看“你将获得什么”、服务清单、妆造时间和锁定总价
→ 标准方案直接下单；非标准方案提交需求等待确认
→ 一次预付款
→ 摄影师与妆造方并行接单
→ 组合订单正式确认
→ 订单页按需开放履约联系方式和精确服务地址
→ 线下履约、交付和分项售后
```

需求卡中的特殊选项默认收进“更多需求”。添加妆造后，每类首屏最多展示 3 个候选，每张候选卡只展示 1—2 张真实作品、名称、风格、上门/到店、时长、价格和一句路线结论；完整作品页只在用户主动点击“查看更多”时打开。

“直接下单”不等于“立即确认”。没有可靠实时档期锁时，用户提交的是固定价格和明确时间的订单请求，摄影师与妆造方接受后才正式成立；页面必须显示“已下单，待服务方确认”。

## 3. 服务、价格和需求单

### 3.1 摄影服务

摄影师为可选择的结构化需求模块预设单位价格，包括但不限于拍摄时长、人数、精修数量、额外交付和服务范围。需求单按照用户选项叠加，服务端计算摄影服务价格。

摄影师收到订单后只做两件事：接受，或因无法满足时间/需求而拒绝。摄影师不得在接单时重写已经展示给用户的价格。

### 3.2 妆造服务

个人妆造师和妆造门店首期各自只上架 1—3 个边界清楚的固定价核心套餐。每个套餐至少明确：

- 套餐名称和适用场景；
- 固定价格和标准时长；
- 适用人数；
- 妆面、发型/基础造型、服装及配件包含范围；
- 明确不包含的内容和可选固定价加项；
- 上门/到店方式、服务区域、准备事项、服装尺码和归还规则；
- 个人妆造师的可服务时段，或门店地址、营业时间和公开营业电话；
- 1—2 张可用于需求卡预览、与实际履约主体一致且已取得展示授权的代表作品。

妆造方自行定价，Still 不擅自修改。套餐变更只影响新订单；已经下单的订单保存不可变的价格、内容、版本和时间快照。个人妆造师的作品必须由本人履约；门店不能用特定员工作品暗示随机分配也能保证同一人或同一效果，除非订单支持指定并锁定该员工。

服装押金不进入 Still 订单。提供服装的个人或门店必须在下单前公开押金、归还、超时和损坏规则；发生争议时由一方在订单内发起客服处理，不允许把未说明费用强制加入平台订单。

### 3.3 用户看到的订单

用户只看到：

- 一份服务清单；
- 一个总价；
- 一次支付；
- 一个订单状态；
- 一个售后入口。

订单内必须清楚标明摄影服务和妆造/服装服务分别由谁提供，但不向用户暴露内部账本和分账操作。

后台以服务项分别保存提供方类型、实际履约主体、套餐版本、价格、时间、地点、接单、履约、退款、佣金和结算状态。妆造不得作为普通 `order_extra` 塞入摄影订单。

## 4. 时间、接单、地址和联系方式规则

### 4.1 妆造时间推荐

当前 App 只通过地图 URI 调起外部地图，无法从 URI 获得路线耗时。MVP 不为了这一功能接入路线 API，也不承诺精确到达时间。

摄影师以用户计划拍摄地点为地理锚点，妆造以用户拍摄前的暂居地（家、酒店等）为地理锚点。匹配阶段只使用区域或模糊位置；组合订单正式确认前，不向个人妆造师或门店返回门牌、房号或用户非必要联系方式。

- 个人妆造师按前往用户暂居地的上门距离、服务区域、可达时间、风格、履约率和价格排序；
- 妆造门店按“暂居地 → 门店 → 拍摄地”的总绕行和衔接风险排序，不能只按门店离用户最近排序；
- 第一版用可解释规则显示“顺路 / 轻微绕行 / 时间偏紧”，不把估算包装成准确路线承诺。

系统按妆造套餐时长、服务方式和用户选择的交通缓冲生成推荐时间：

| 场景 | 默认缓冲 |
| --- | ---: |
| 个人妆造师上门至暂居地 | 15 分钟 |
| 门店到拍摄地附近步行 | 30 分钟 |
| 门店到拍摄地需要乘车 | 60 分钟 |
| 路线不确定 | 90 分钟 |

用户可以调整期望妆造时间。系统只禁止明显无法在拍摄前完成的组合；其余通过“衔接宽松/推荐/偏紧”提示风险，不替用户保证实际交通。

### 4.2 并行接单

用户确认服务清单后一次预付款，摄影师和妆造方并行收到同一组合订单中属于自己的服务项：

- 摄影师普通订单：4 个有效接单小时；默认接单时段 09:00—22:00，摄影师可在规则范围内配置；时段外暂停计时；
- 个人妆造师普通订单：2 个有效接单小时，以本人已公布可接单时段计时；
- 门店普通订单：2 个有效营业小时，以门店已公布营业时间计时；
- 距离最早服务不足 24 小时：只向主动开启“紧急可接单”的服务方发单，确认时限 30 分钟。

接单前服务方可以拒绝；接单后即承诺订单中的时间、价格和服务范围。拒绝必须选择原因，超时等同拒绝并释放相关临时占用。

分支规则：

- 摄影师拒绝或超时：主服务无法成立，整单取消并原路全额退款；
- 妆造方拒绝或超时：用户可保留摄影并退回妆造服务金额，或取消整单并全额退款；
- 用户收到妆造方拒绝通知后，普通订单有 2 个有效小时作选择，紧急订单有 30 分钟；未选择则默认取消整单并全额退款。

### 4.3 地址和联系方式显示

成交前绝对不显示个人妆造师私人电话、门店非公开电话或用户精确暂居地址，也不要求用户先电话预约。只有摄影师和妆造方都接受、组合订单正式确认后，订单页才按履约必要性显示个人平台联系入口、门店公开营业电话或精确服务地址。

电话只用于：

- 临近服务时间再次核对；
- 询问路线、到店方式和准备事项；
- 沟通服装尺码、头发状态等已成交服务细节。

用户不打电话不影响预约效力。电话中不得改价、要求线下支付或绕过 Still 取消订单；时间变化必须回到订单内由受影响方确认。

## 5. 迟到、取消、异常和改期

### 5.1 默认正常履约

服务时间经过后默认按正常流程推进。系统不按迟到分钟数自动罚款，不因为距离拍摄时间接近而静默取消，也不把提醒当作异常证据。

现场允许像理发、美甲一样由双方协调顺延、调整次序或在同意的范围内压缩服务。只有一方主动发起“服务异常/申请取消”后，平台才进入归责流程。

### 5.2 取消和归责矩阵

| 情况 | 处理 |
| --- | --- |
| 摄影师或妆造方尚未全部接受 | 取消相关未确认交易，全额退款 |
| 距最早服务超过 24 小时，用户取消 | 全额退款 |
| 距最早服务不足 24 小时，且确认由用户迟到/失约导致 | 退还受影响服务项 80%的服务价值；20%作为全额归服务方的非计佣档期补偿 |
| 服务方原因无法履约 | 受影响服务项全额退款，服务方不结算；摄影师为主服务方时整单取消 |
| 双方协商一致或无法明确归责 | 全额退款 |
| 对事实或责任存在争议 | 客服接入，按证据处理 |

20%只适用于已经确认且确有用户责任的受影响服务项，不自动扩展到未受影响服务。该 20% 全额作为非计佣档期补偿进入受影响服务方应结金额，不再收取 8% 平台佣金。

### 5.3 改期

原则是：能不改的就不改，只重新确认受影响服务项。

- 只调整妆造时间：用户和妆造方确认，摄影时间不变；
- 同日拍摄向后延迟，且妆造时间、套餐、地点、服装归还或妆造方现场安排不受影响：只需用户和摄影师确认，妆造方收到通知但无需重新接单；
- 拍摄提前、跨日、地点变化，或影响妆造/服装服务：用户、摄影师和受影响妆造方重新确认；
- 同一服务方、同一套餐内容的改期保持原锁定价格；用户主动改变时长、套餐或服务内容时按差价重新确认。

## 6. 佣金、结算和退款资金规则

### 6.1 试点商务数字

- 试点周期：首笔真实组合订单起 30 个自然日，或 10 笔已完成组合订单，先到为准；
- 入驻费、软件费、年费：0 元；
- 摄影、个人妆造师和门店服务项平台佣金：分别按各自服务项的计佣基数收取 8%；
- 支付通道手续费和平台主动优惠：MVP 由 Still 承担；
- 试点非独家，不要求个人妆造师或门店预留 Still 专属档期/库存；
- 试点结束后，费率和范围只有经书面确认才改变，不自动涨价或转为收费软件。

金额统一按以下口径计算：

1. `计价金额 = 锁定原价－服务方明确承担的优惠`；平台优惠券不降低计价金额；
2. `用户应付 = 计价金额－分摊到该服务项的平台优惠`；平台补足这部分优惠；
3. `计佣基数 = 计价金额－按服务价值计算的退款－非计佣档期补偿`；
4. `服务方应结金额 = 计佣基数 × 92%＋非计佣档期补偿`；
5. 支付通道手续费不从服务方应结金额中扣除。

固定验收样例：

- 正常履约 100 元：平台佣金 8 元，服务方应结 92 元；
- 使用 10 元平台券：用户支付 90 元、Still 补足 10 元，服务方仍应结 92 元；
- 用户责任取消且按 80%/20%处理：退还 80 元服务价值，服务方获得 20 元非计佣档期补偿，平台佣金 0 元。

平台优惠在支付时按服务项留下不可变分摊快照。发生退款时，优惠券按该服务项退款比例退回；原券失效则等值补发，现金退款不得超过该服务项用户实际支付金额。该数字和公式需要在 `WIN-SETTLE-1` 中成为服务端版本化规则，清理现有前后端 8%、10%、15% 的不一致；客户端不得自行计算最终佣金或退款。

### 6.2 服务项结算

用户侧仍是一个订单，但结算以服务项为单位：

1. 服务方标记服务完成后，用户主动确认即可让该服务项进入可结算，也可以发起异常；
2. 若用户未操作，服务计划结束后 72 小时且无异常，该服务项自动进入可结算；
3. 每个服务项按计价金额、平台优惠分摊、退款、8%佣金和非计佣补偿形成独立应结算金额；
4. 妆造服务完成后不等待摄影师后期交付；摄影服务按其交付与完成规则进入结算；
5. 原则上只冻结有争议的服务项；只有支付异常、责任无法拆分或整单欺诈风险时才冻结整单；
6. 平台按经支付机构、合规和财务确认的方案处理资金，不能在未取得相应能力时对外使用不准确的“资金托管”表述。

平台先行退款或赔付后，可依据已通知、可申诉、证据可审计的裁定，从责任方未结算金额中扣回；不足部分进入人工追偿，不允许形成不可解释的负余额。

## 7. 妆造方最小产品

冷启动采用同一 Still 代码库中的轻量移动 Web 妆造方工作台，不开发独立妆造 App，也不安装本地 SaaS。个人妆造师和门店由运营协助入驻，只需要：

- 待接单：查看用户已预付的明确时间、人数、套餐和必要需求，接受或拒绝；
- 已确认订单：查看服务清单、时间、上门/到店信息和履约操作；
- 套餐与作品：维护 1—3 个固定套餐和少量真实作品并提交审核；
- 服务设置：个人维护可服务时段/区域和上门开关，门店维护营业时间、地址、公开营业电话和紧急接单开关。

MVP 不做：

- 员工、工位和全渠道库存管理；
- 美团、抖音或门店收银系统同步；
- Still 专属保证名额；
- 自动判断现场等待、迟到或妆造方并发能力；
- 成交前电话咨询链路。

## 8. 个人与门店合作定位和准入

对个人妆造师的统一表达为：

> 把您的真实作品、擅长风格、上门区域和固定套餐直接展示给已经确定拍摄需求的用户，减少反复询价和无效沟通。

对门店不使用“解绑摄影馆和摄影师”。统一表达为：

> 不影响您现有摄影套餐，新增一条面向“已经选好摄影师、仍需要妆造或服装”的增量服务渠道。

一句话价值主张：

> Still 不要求门店更换现有系统、预留专属库存或放弃原有摄影套餐；门店只需上架 1—3 个自己定价的标准妆造/服装服务，对时间和需求明确、已经完成预付款的订单逐笔决定是否承接。

妆造方准入必须满足：

- 个人提供真实身份、本人作品、可服务区域和可接单时段；门店提供真实经营主体、门店地址、营业时间和公开营业电话；
- 套餐价格、时长、适用人数、包含和不包含内容清楚；
- 接受成交后锁价，不强制线下支付或隐性加价；
- 能在有效营业时间内处理订单，接单后按确认内容履约；
- 接受平台取消、退款、证据留存、申诉和争议处理规则；
- 服装相关押金、尺码、归还和损坏规则提前公开；
- 关联摄影师的合作关系由双方确认。

Still 对妆造方承诺：

- 接单前展示判断所需的结构化需求；
- 成交前不公开双方私密联系方式或用户精确暂居地址；
- 不擅自修改妆造方服务价格；
- 不要求专属名额、系统迁移或渠道独家；
- 用户先预付，订单、退款和责任记录在同一入口；
- 试点阶段协助整理套餐、录入资料和完成模拟订单。

Still 不承诺订单量、收入、稳定曝光、绝对准时、准确路程、无投诉或当前已经具备实时库存。

## 9. 30 天受控试点

### 9.1 试点范围

- 2—4 名个人妆造师和 2—4 家妆造门店，每个提供方 1—3 个标准套餐与少量已核验作品；
- 个人设置平台联系入口和服务区域，门店设置公开营业电话和一名订单负责人；
- 少量双方确认的真实合作摄影师；
- 不独家、不装本地软件、不预留库存；Still 不同步或接入美团、抖音等外部平台订单与库存，门店原渠道和个人原有接单渠道照常使用；
- 每个提供方先跑一笔模拟订单；模拟通过只是必要条件，支付、部分退款、分项结算、权限、合规和财务闸门全部通过后才开放真实受控订单；
- 真实试点至少分别完成一笔个人上门妆造和一笔门店到店妆造；
- 妆造方可暂停新订单，但不得影响已确认订单。

### 9.2 成功和停止条件

每周至少记录：

- 发单量、个人/门店接受率、各方平均响应时间；
- 组合订单确认率、保留摄影比例、完成率和取消率；
- 用户实际等待、妆造方延误、迟到和争议；
- 个人/门店新增实收金额和每单额外操作时间；
- 是否发生强制加价、电话二次预约、线下绕单或责任不清；
- 用户满意度、两类妆造方继续意愿和套餐扩展意愿。

出现以下任一情况，暂停扩大：

- 真实支付、部分退款、分项结算或权限隔离未通过验收；
- 妆造方无法稳定承诺已接受的明确时间；
- 用户精确暂居地址或双方私密联系方式在正式确认前泄露；
- 组合订单纠纷明显高于单摄影订单且规则无法解释；
- 个人或门店新增收入不足以覆盖操作成本；
- Still 需要靠人工改价、伪造库存或线下收款维持流程。

## 10. 内容、关注和作品边界

- 普通用户主页可展示个人介绍和其主动公开的 Still 真实订单作品；不能上传站外摄影、日常或无关内容；
- 关注功能保留，用于追踪拍摄足迹和进入“拍同款”；
- 摄影师可为冷启动发布站外作品，但必须标注“摄影师作品集”，与 Still 订单作品分区；
- 一张订单作品在后台可以关联用户、摄影师、妆造方、订单和服务项，首页仍以作品和摄影师为主，不平铺所有关系；
- 评论、社交私信、转发链和排行榜不随本试点自动开放；交易咨询与客服沟通保留；
- 订单完成后可生成九张独立图片、九宫格、文案、话题、署名、地点和 BGM 搜索关键词，但不建设完整修图或剪辑软件。

## 11. Agent 长期路线

Agent 后置并内置于产品，不作为首页独立入口或当前妆造试点卖点。首期能力只包括：

- 理解自然语言；
- 拆解拍摄需求；
- 填写与手动菜单相同的结构化字段；
- 提醒用户检查缺失或互相冲突的选项。

菜单始终保留，用户可以查看、修改和删除 Agent 填写的任何字段。当前个人妆造师和门店都没有可靠实时档期同步，因此 Agent 最多生成期望妆造时间和可确认的订单草稿，不能承诺预约成功。

Agent 不得自动付款、改价、取消、替服务方接单或绕过用户最终确认。Vibe、审美指导和智能排期只有在真实供给、服务项、库存、偏好和履约数据成熟后另行立项。

长期领域模型保持模块化：摄影、妆造、服装和未来场地都是可组合服务项；摄影师与个人妆造师/门店是可组合关系，不把妆造方所有权硬编码到摄影师账户中。

## 12. 实施顺序和发布边界

1. 按个人/门店双供给方案重写合作规则、商务数字、合规措辞、Word/PPT 和 30 天试点确认单；
2. 建立统一妆造提供方、固定套餐、真实作品、合作关系和订单服务项领域骨架，功能开关默认关闭；
3. 实现以暂居地为锚点的个人上门推荐、门店绕行推荐和需求卡 1—2 张作品快选；
4. 重构需求卡为极简预选，打通标准方案直接下单与非标准方案咨询报价的同一事实源；
5. 在真实支付、部分退款和结算基础完成后，实现一次预付、并行接单和分支退款；
6. 完成用户、摄影师、个人妆造师、门店和 Admin 的跨角色、跨设备、金额守恒、地址与联系方式脱敏验收；
7. 每个提供方模拟订单通过，且支付、部分退款、分项结算、权限、合规、财务与跨角色验收全部通过后，才开放少量真实受控订单；
8. 分别完成个人上门和门店到店真实样本，以接受率、履约、满意度和单位经济决定继续、调整或停止，不以注册量和页面数量代替验证。

`INT-COMBO-1` 完成前禁止真实组合支付。妆造相关功能必须由默认关闭的功能开关控制；关闭后不能影响当前纯摄影订单、P0 Release Candidate 或 App Store 主流程。2026-08-20 版 Word/PPT 仍按“仅门店”编写，在按本版重写并重新渲染验收前只能作为历史材料，不能用于真实招募承诺。
