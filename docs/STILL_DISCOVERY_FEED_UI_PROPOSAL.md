# Still 发现页图片流 UI 修改方案（讨论稿）

> 状态：讨论中，**不构成代码实施授权**。<br>
> 版本：v0.1（2026-08-04）<br>
> 范围：仅用户端首页的「发现」频道图片流；不涉及订单、摄影师详情、数据接口或其他频道的业务规则。

## 1. 目标

将发现页从紧密的双列瀑布流，调整为更接近摄影编辑墙 / 专辑墙的图片流：作品比例优先、节奏清晰、信息克制。页面仍然是沉浸式浏览，不改造成带卡片标题和价格的交易列表。

本次只讨论图片流本身；顶部透明频道和底部悬浮导航是既有页面骨架，必须保持原位置与覆盖关系。

## 2. 已确认的视觉决策

### 2.1 页面骨架保持不动

- 顶部继续使用原有透明覆盖层：城市入口、`关注 / 发现 / 附近`、搜索与筛选按钮均保留；`发现`为选中频道。
- 顶部组件继续叠在首屏作品上，不新增实体标题栏、快速筛选条或额外安全区留白。
- 底部继续使用原有黑色悬浮导航，并保持其与屏幕底部、图片流之间的原始距离和覆盖位置。
- 图片流仍从页面顶部开始向下滚动；本方案的间距不改变顶部或底部组件的坐标。

### 2.2 图片流规则

- 图片卡片采用 **0px 圆角（直角）**，不使用圆角卡片感。
- 当前偏好方案为：左右页面内边距、两列横向间隔、行与行的纵向间隔均使用 **12px**。
- 12px 仅指图片流的左右外边距及图片之间的间隔；不在图片流顶部或底部额外补出 12px 留白。
- 优先完整表达原图比例，不以整齐方格为目标；不得为了填满格子而把纵向作品裁成正方形或大幅裁切。
- 纵向作品以两列成组呈现；横向作品插入时单列占满内容宽度，之后回到下一组双列纵向作品。
- 成对呈现的纵向作品应优先选择比例接近的素材；若比例差异过大，宁可重排或让其作为宽图呈现，也不牺牲作品比例强行对齐。

建议的首屏节奏：

```text
双列纵向作品
        ↓
全宽横向作品
        ↓
双列纵向作品
        ↓
继续按素材比例重复
```

### 2.3 作品信息：一行、只保留必要信息

- 每个作品底部保留一条轻量渐变信息层：`地点`在左、`点赞数`在右。
- 地点和点赞数是发现流的必备信息；保持现有的小字号、白色文字与图标层级。
- 不在发现流展示价格、评分、可约状态、头像、摄影师名、出镜人名或第二行描述。
- 摄影师和出镜人信息进入作品详情、摄影师主页或点击后的上下文，不与地点/点赞数竞争首屏注意力。

## 3. 参考调研结论

调研优先级按 Pageflows → Godly / Recent → Mobbin 执行，结论用于提炼原则，不复制任何单个产品的界面。

| 来源 | 观察 | 对 Still 的取舍 |
| --- | --- | --- |
| [Pageflows](https://pageflows.com/) | 内容浏览与全局导航应有清晰层次，内容本身优先承载注意力。 | 顶部频道保持轻、透明、覆盖；不在首屏叠加多层筛选组件。 |
| [Godly / Recent](https://recent.design/app-store-screenshots) | 影像类产品通常以大面积媒体、少量元信息和一致节奏形成高级感。 | 保留地点与点赞，删除价格和多行人员信息。 |
| [Mobbin](https://mobbin.com/explore/mobile/screens/browse-discover) | 发现页中导航、筛选与内容卡是不同层级；信息密度过高会削弱媒体浏览。 | 不把快速筛选条、交易字段混进图片流；图片间距成为主要节奏。 |

## 4. 与当前实现的差异（供 Roadmap 对话实施时使用）

当前关联模块：

- `pp-app/src/features/user/HomeFeed.tsx`：发现频道、顶部交互及页面容器。
- `pp-app/src/features/user/PhotoFeed.tsx`：图片流分段、双列布局、横图插入、推荐模块和间隔。
- `pp-app/src/features/user/PhotoCard.tsx`：作品封面比例、媒体展示、地点与点赞元信息。

实施方向（仅方案，不在本对话修改）：

1. 将图片流的 `1px` 左右内边距和横纵间隔统一替换为 12px；不要因此增加页面顶部或底部留白。
2. 把布局调度改为“纵图双列组 + 横图全宽行”的顺序化节奏，而非在两个独立列中无限延伸的瀑布流。
3. 取消发现流中插入的地点、摄影师、同风格推荐条和人为平衡空白；它们会打断作品墙的连续性。如需保留推荐，应另行设计为独立内容段落后再评审。
4. 取消由 `tall / portrait / soft` 固定比例造成的过度裁切；应依据媒体自身比例选择对应版式，并用最小裁切策略展示。
5. 保留 `PhotoCard` 的单行地点 + 点赞信息层；不新增价格、评分、摄影师或出镜人字段。
6. 不改动顶部透明频道、搜索/筛选入口、底部悬浮导航的结构、定位、尺寸或层级。

## 5. 验收标准

最终实施前后应使用同一批作品截图对照，并同时满足：

- [ ] `关注 / 发现 / 附近`、城市、搜索/筛选和底部导航与原页面处于相同位置；没有额外顶端或底端留白。
- [ ] 图片均为直角，无圆角、投影或独立白/黑卡片边框。
- [ ] 页面左右内边距、横向卡片间隔、纵向卡片间隔均为 12px。
- [ ] 纵向图片成双列，横向图片完整占一行；横图之后能自然接回双列。
- [ ] 未把纵图裁成方图，也未因布局破坏横图的横向构图。
- [ ] 每张作品只有地点与点赞数一行元信息；发现页无价格、评分、可约状态、人员名称、头像或第二行文字。
- [ ] 首屏与连续滚动中没有因重新排版导致的图片闪烁、跳动或 Live Photo 回退。
- [ ] 小屏和 iPhone 真机上，图片流不被底部悬浮导航意外遮住关键交互内容。

## 6. 尚待最终确认的事项

1. **12px 是否最终定稿**：当前是二选一中的推荐值；确认后作为设计 token 固化。
2. **不同纵图比例的配对阈值**：需要用真实作品库检查何种比例差仍可并列，超过阈值时如何重排。
3. **插入式推荐模块**：本方案建议从发现流移除；若业务需要保留，需另做独立的视觉方案后再加入。
4. **元信息的地点文案格式**：继续使用“上海 · 地点”，或在城市已由顶部表达时仅显示具体地点，待最后的真机截图确认。

## 7. 讨论与实施边界

- 在本方案被明确确认前，不修改 `HomeFeed`、`PhotoFeed`、`PhotoCard` 或图片数据结构。
- 方案确定后，在 Roadmap 对话中按本文件第 4、5 节实施并做构建与真机/截图回归。
- 若后续决定加入摄影师、出镜人、价格或“今日可约”信息，应重新评审其是否属于发现流，默认放在详情或筛选层而非作品底部。
